# CDN Combo Endpoint

## Goal

Serve custom component bundles via URL — a comma-separated list of components or a named preset in a single `<script>` tag. No import map, no configuration. The URL IS the component manifest.

```html
<!-- Explicit components -->
<script type="module" src="https://cdn.semantic-ui.com/core@0.18.0/button,input,modal"></script>
<link rel="stylesheet" href="https://cdn.semantic-ui.com/semantic-ui.css">

<!-- Named preset -->
<script type="module" src="https://cdn.semantic-ui.com/core@0.18.0/standard"></script>
```

This replaces the need for a monolithic `semantic-ui.min.js` bundle that grows with every component. At 70+ components, a full bundle is unreasonably large. The combo endpoint loads only what you specify.

## Why This Matters

- **AI agents in sandboxes** — one `<script>` tag, no import map ceremony, URL tells you exactly what's loaded. Add a component by appending to the URL.
- **Production sites** — load only the components you use, deduplicated deps, individually cached.
- **Getting started** — the simplest possible onramp. Simpler than import maps, simpler than bundlers.
- **Scales to 70+ components** — no combinatorial explosion, no pre-computation. The Worker generates shims on the fly.

## Design

### URL Structure

```
cdn.semantic-ui.com/core@0.18.0/button,input,modal     → explicit list
cdn.semantic-ui.com/core@0.18.0/standard                → preset (~15 common components)
cdn.semantic-ui.com/core@0.18.0/form                    → preset (form-related components)
cdn.semantic-ui.com/core@canary/button,menu              → canary channel
```

### How It Works

The Worker detects a combo URL (comma-separated names or preset name), generates a tiny JS module that imports the CDN format version of each component:

```js
// Generated by Worker for /core@0.18.0/button,input,modal
export * from "https://cdn.semantic-ui.com/core@0.18.0/button.js";
export * from "https://cdn.semantic-ui.com/core@0.18.0/input.js";
export * from "https://cdn.semantic-ui.com/core@0.18.0/modal.js";
```

Each CDN format file has its imports rewritten to full CDN URLs internally. The browser:
1. Fetches the shim (one request)
2. Follows the imports to each component's CDN file (parallel)
3. Those files import shared deps (component, lit, utils) via full URLs
4. Browser deduplicates by URL identity — shared deps loaded once
5. All files cached individually — adding a component later reuses existing cache

No import map needed. No bundled dep duplication. Full deduplication via the CDN format's pre-rewritten imports.

### Presets

Named presets expand to component lists. Defined in the Worker or a manifest in R2.

| Preset | Components | Use case |
|---|---|---|
| `standard` | button, input, label, icon, image, menu, segment, container, divider, card, table, spinner, modal | Common UI — covers most prototypes |
| `form` | input, checkbox, radio, select, switch, form, form-field, textarea | Form building |
| `layout` | container, segment, rail, divider, card, table | Page structure |
| `all` | Every component | Equivalent to the old monolithic bundle |

Presets evolve as more components are built. The `standard` preset is the default recommendation for getting started.

### Bundle Endpoint (separate, simpler)

The combo endpoint uses CDN format files (deduplicated, multi-request). A separate `/bundle/` path serves self-contained single-file bundles for cases where zero import chain is preferred:

```
cdn.semantic-ui.com/core@0.18.0/bundle/button.min.js     → single file, all deps inlined
cdn.semantic-ui.com/core@0.18.0/bundle/semantic-ui.min.js → full framework bundle
cdn.semantic-ui.com/component@0.18.0/bundle               → bare URL → component.min.js
```

The bundle endpoint is simpler but fatter — each file includes all deps. Best for single-component use cases. The combo endpoint is better for 2+ components.

### Cache Strategy

- **Combo shim** — short TTL or ETag-based. The shim is tiny (<1KB) and just contains imports.
- **Individual CDN files** — `immutable` for versioned, short TTL for canary. Already cached from existing CDN pipeline.
- **Presets** — same as combo shims. Could be pre-generated at upload time.

### Getting Started (Updated)

With the combo endpoint, the getting started experience becomes:

```html
<!DOCTYPE html>
<html>
<head>
  <link rel="stylesheet" href="https://cdn.semantic-ui.com/semantic-ui.css">
  <script type="module" src="https://cdn.semantic-ui.com/core@canary/standard"></script>
</head>
<body>
  <ui-button primary>Click Me</ui-button>
  <ui-input placeholder="Type here"></ui-input>
</body>
</html>
```

Two lines in `<head>`. No import map. No configuration. Works.

## Implementation

### Worker Changes (`tools/cdn/worker/index.js`)

1. Detect combo URLs: filepath contains commas → combo, filepath matches preset name → expand preset
2. Generate the import shim JS
3. Serve with `Content-Type: application/javascript`
4. Cache the generated shim (same combo URL → same response)

### Upload Changes (`tools/cdn/upload.js`)

1. Upload `dist/bundle/` alongside `dist/cdn/` for each SUI package
2. Upload a preset manifest to R2 (`_meta/presets.json`)

### Preset Manifest

```json
{
  "standard": ["button", "input", "label", "icon", "image", "menu", "segment", "container", "divider", "card", "table", "spinner", "modal"],
  "form": ["input", "checkbox", "radio", "select", "switch", "form", "form-field", "textarea"],
  "layout": ["container", "segment", "rail", "divider", "card", "table"]
}
```

Updated when components are added. Uploaded alongside import maps during the publish pipeline.

## Future: Build Service (Option C)

If download size becomes a concern, a Cloudflare Worker running esbuild via WASM could produce truly deduplicated single-file combo bundles on demand. The URL format stays the same — switching from shim-based to build-based is invisible to the consumer. Cache results in R2 keyed by component list + version.

This is the "real" CDN combo build but requires more infrastructure. The shim approach is the right starting point.
