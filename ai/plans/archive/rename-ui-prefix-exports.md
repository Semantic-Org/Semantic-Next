# Plan: Remove UI Prefix from Component Exports

## Decision
Rename all `UIButton` → `Button`, `UICard` → `Card`, etc. across the codebase. The `UI` prefix is redundant with the `@semantic-ui/core` import path, adds visual noise in templates at scale, and goes against industry convention. Web component tags (`<ui-button>`) are unchanged — they require the hyphen.

## Special Case: MenuItem spec
The `menu-item.spec.js` has `exportName: "UIMenuItem"` but the actual export is already `MenuItem`. The spec should be corrected to `MenuItem` as part of this work.

## Not Changed
- Web component tag names (`<ui-button>`) — required by HTML spec
- `tagName` properties in defineComponent calls — unchanged
- `UIWebComponent` base class in `packages/component/types/` — internal base class, not a component export
- `MenuItem`, `Spinner` — already unprefixed
- Examples in `examples/` — use web component tags directly, not JS exports
- Generated files (`.spec.json`, `.component.js`) — regenerated by build

## Execution Order

### Phase 1: Source definitions (src/primitives/)
Rename the `const` definitions and `export` statements in each component's implementation file and index.js. This is the source of truth — everything else imports from here.

Files per component:
- `src/primitives/{name}/{name}.js` — `export const UIX` → `export const X`
- `src/primitives/{name}/index.js` — `export { UIX }` → `export { X }`
- `src/primitives/{name}/plural/{names}.js` — (where applicable)
- `src/primitives/index.js` — barrel re-exports

### Phase 2: Spec source files (src/primitives/**/specs/*.spec.js only)
Update `exportName` and `pluralExportName` fields in `.spec.js` files only. The `.spec.json` and `.component.js` files are generated — they'll be regenerated by the build.

Also fix `MenuItem` spec (`exportName: "UIMenuItem"` → `"MenuItem"`).

### Build checkpoint: `npm run build`
Regenerates `.spec.json`, `.component.js`, and dist bundles with correct export names. Validates Phase 1+2 didn't break anything.

### Phase 3: Internal consumers (src/components/)
Update imports in doc-site components that use primitives:
- `global-search.js` — UIIcon, UIInput, UIModal
- `inpage-menu.js`, `sidebar-toggle.js`, `mobile-menu.js`, `topbar-menu.js`, `theme-switcher.js`, `nav-menu.js`, `copy-button.js`, `mobile-menu-toggle.js` — UIIcon

### Phase 4: Docs site (docs/src/)
Update imports and usage in:
- `UIComponent.astro`, `UIComponentStatic.astro` — big import lists
- `Sidebar.astro`, `DocsMasthead.astro`, `Layout.astro`
- `pages/index.astro`
- `CodeExample.js`, `LearnExample.js`, `AIPrompt.js`

### Build docs + manual browser verification
`npm run build:docs` — user verifies in browser.

### Phase 5: AI/docs content
Update references in ai/skills/ markdown files that show import examples.

### Phase 6: Type definitions (cosmetic)
- `packages/specs/types/index.d.ts` — update comment example `"UIButton"` → `"Button"`
