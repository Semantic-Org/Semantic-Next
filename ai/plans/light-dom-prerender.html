No changes to framework behavior. --- ## Phase 1: Non-Reactive Rendering Mode **Goal:** The existing renderer can run in a mode where expressions evaluate once without creating Signals or Reactions. Same tree-walk, same expression evaluator, same data context — just skipping reactive wiring. ### 1.1 — Rendering mode flag The renderer (Lit or Vanilla) needs a mode where each expression takes the `getReactiveValue()` path (one-shot evaluation) instead of `watchChanges()` (Reaction creation). The SSR path already does this via `isServer`. The pre-render mode is a third context: ```js // In ReactiveDataDirective.render() or VanillaRenderer equivalent if (this.renderMode === 'prerender' || isServer) { value = this.getReactiveValue(); // one-shot, no Reaction } else { value = this.watchChanges(); // Reaction.create + subscribe } ``` The mode flag flows from `defineComponent` → `Template` → Renderer → each directive/binding. ### 1.2 — `createComponent` in nonreactive closure `createComponent` must run to provide the data context (methods like `addOne()`, `isTrue()`). `Reaction.nonreactive()` wraps the entire pre-render pass — real Signals initialized from `defaultState`, real expression evaluation, zero dependency tracking: ```js function prerenderInstance(def) { return Reaction.nonreactive(() => { // Real signals from defaultState — reads work, no tracking const state = {}; for (const [k, v] of Object.entries(def.defaultState || {})) { state[k] = signal(v); } const settings = { ...def.defaultSettings }; // Real createComponent — only side-effectful params need stubbing const instance = def.createComponent({ state, settings, signal, self: null, reaction: () => {}, // stub: don't register ongoing work interval: () => {}, // stub: don't start timers timeout: () => {}, // stub: don't schedule attachEvent: () => {}, // stub: don't bind events bindKey: () => {}, // stub: don't bind keys dispatchEvent: () => {}, // stub: don't emit findParent: () => null, // stub: no DOM tree yet findChild: () => null, findChildren: () => [], isClient: true, isServer: false, isRendered: () => false, $: () => emptyQuery, $$: () => emptyQuery, el: null, }); instance.self = instance; // DON'T call initialize() — it contains side effects return { state, settings, instance }; }); } ``` `state.items.get()` returns `[1,2,3]`. `instance.addOne(1)` returns `2`. All pure computation works with real values. Only side-effectful params (`reaction`, `interval`, `timeout`, `attachEvent`, `bindKey`) are stubbed because they register ongoing work that shouldn't exist during pre-render. **Test cases:** - Component with methods referencing `self` — circular ref patched correctly - Component with methods calling `state.x.get()` — returns real initial value - Component with methods calling `settings.x` — returns default setting - TodoMVC `createComponent` — all methods return sensible values - Verify zero Reactions created during the nonreactive closure ### 1.3 — Light DOM output target The renderer's output attaches to the element itself (light DOM children) instead of a shadow root: ```js // Pre-render: output to light DOM const fragment = renderer.render({ ast, data }); element.appendChild(fragment); // Full render: output to shadow root const shadow = element.attachShadow({ mode: 'open' }); shadow.appendChild(renderer.render({ ast, data })); // or for Lit: shadow returns TemplateResult ``` The tree-walk DOM construction is identical. Only the attachment point differs. **Validation:** - Same AST produces structurally identical DOM in both modes - Expressions evaluate to same values in nonreactive vs reactive mode (for pure functions) - Pre-rendered DOM matches full-render DOM minus reactive subscriptions --- ## Phase 2: Slot Projection **Goal:** Consumer-provided children appear at correct positions in pre-rendered template, reversible on upgrade. ### 2.1 — Stash consumer children Before template render, collect element's children keyed by slot name: ```js function stashChildren(el) { const stashed = { default: [] }; for (const child of Array.from(el.childNodes)) { if (child.nodeType === 3 && !child.textContent.trim()) continue; // skip whitespace const slotName = (child.nodeType === 1 && child.getAttribute('slot')) || 'default'; if (!stashed[slotName]) stashed[slotName] = []; stashed[slotName].push(child); if (child.nodeType === 1 && child.hasAttribute('slot')) { child.__originalSlot = slotName; child.removeAttribute('slot'); } } el.__suiPrerender = { children: stashed }; return stashed; } ``` ### 2.2 — Slot replacement in rendered fragment When the renderer encounters a `slot` AST node during pre-render: 1. Create `` wrapper (NOT hyphenated — see TDD) 2. Move matching stashed children into it 3.
