# Renderer — each reconciliation, FGR, async block, update granularity

The native renderer (packages/renderer/src/engines/native) compiles templates to an HTML string with comment markers, clones it, and wires one Reaction per dynamic site: per text expression, per attribute, per block ({#each}, {#if}, {#async}, {>subtemplate}, {#rerender}/{#guard}). There is no vdom — invalidation granularity equals what each Reaction's evaluation read. {#each} is fully keyed (Signal.id: id/_id/hash/key, positional fallback) with a lit-style head/tail reconcile, LIS-minimal DOM moves over marker-bounded item ranges, and a Phase-3 per-field snapshot diff that fires per-FIELD Dependencies (ReactiveDataContext) so only bindings reading a mutated top-level doc field re-fire — surviving item DOM is moved, never rebuilt. Full array replacement and in-place signal-helper mutation converge on the same reconcile; the renderer rewards stable doc ids, reference-preserved unchanged docs, and top-level field-reference replacement for nested changes (the diff and field deps are both depth-1). Subtemplate reactiveData and snippet args get structural per-key isolation via lazy native-getter records whose reads register source-signal deps directly on the reading binding's Reaction. {#async} is the only async primitive: loading/success/error states with a stale-generation guard, wholesale region re-render per resolution — suited to one-shot promises, while live queries should be Signals feeding {#each}.

## APIs

### {#each} keyed reconciliation (eachBlock.reconcile)

One Reaction per {#each} block (wired by defineBlock at /home/jack/semantic/next/packages/renderer/src/engines/native/define-block.js:206-235). On invalidation, update() re-reads the items expression and runs reconcile() (/home/jack/semantic/next/packages/renderer/src/engines/native/blocks/each.js:224-491). KEYED: keys come from getItemID (/home/jack/semantic/next/packages/renderer/src/shared/each.js:15-30) — plain objects use Signal.id = item.id ?? item._id ?? item.hash ?? item.key (/home/jack/semantic/next/packages/reactivity/src/signal.js:29), falling back to positional index; strings key as value+':'+index; keys are stringified. Phase 1 is a lit-html-style head/tail walk (each.js:237-306) that lazily builds key→index maps only for non-contiguous changes; removed records get disposeRecord (scope.dispose + dataContext.dispose + marker-bounded DOM teardown, each.js:184-188). Phase 2 linearizes DOM with minimal moves via LIS of old positions (each.js:329-364, /home/jack/semantic/next/packages/renderer/src/shared/lis.js:9-33); a surviving record's DOM is NEVER rebuilt, only moved by extracting its startMarker..endMarker range into a fragment (each.js:97-106) — item DOM identity (focus, inner block state) is preserved. Phase 3 is per-key data update (each.js:366-487): same-ref items run a shallow per-field snapshot diff (refreshSnapshotAndDetect, each.js:61-73, `snapshot[k] !== item[k]` reference compare per top-level field) and fire dataContext.notifyField(key) only for changed fields; ref-changed-but-key-matched items (e.g. fresh doc objects from a re-emitted query) take the same diff path (each.js:402-434) so only mutated-field bindings re-fire; index changes fire only the index key (each.js:424-427). Empty-array fast path skips reconcile entirely and tears down records (each.js:758-773).

### Full array replacement vs in-place mutation (Signal write paths)

Replacement: signal.set(newArray) runs equality first — default Signal.equality = isEqual, a DEEP structural compare (/home/jack/semantic/next/packages/reactivity/src/signal.js:27,79-84; /home/jack/semantic/next/packages/utils/src/equality.js:15-28). Deep-equal replacement is a silent no-op (good dedup, but O(n·fields) compare per emit on big result sets). If different → notify() → the each block's single Reaction re-runs reconcile; per-item DOM updates are still limited by key match + field diff. In-place mutation: array helpers push/unshift/splice/map/filter/setIndex/removeIndex/setIndexProperty/setItemProperty/toggleItemProperty/setProperty/replaceItem/removeItem all mutate currentValue directly and ALWAYS notify, skipping clone+compare (signal.js:165-222, 281-347). Both paths converge on the same reconcile; with in-place mutation, unchanged items hit the same-ref branch (each.js:465-485) which costs only one ref-compare per field per item. Signal.mutate(fn) uses trackWrites for change detection (signal.js:138-158). Default safety='reference' means .get()/.value return the live reference (signal.js:63-77); safety:'clone' returns fresh refs each read — each.js handles this (refChanged + key match path, comment each.js:377-381) but degrades every reconcile to the diff path.

### ReactiveDataContext — per-item, per-key, per-FIELD isolation (FGR)

Each {#each} record owns a ReactiveDataContext (/home/jack/semantic/next/packages/renderer/src/engines/native/reactive-context.js:240-332): a Proxy fronting the parent context with per-key Dependency objects in null-proto bags. trapGet (line 109-150) registers a per-key dep on the running Reaction; misses fall through to parent (with a keySetVersion late-key dep unless sealed). As-mode ({#each todos as todo}): the as-key returns an item-tracking proxy (ITEM_HANDLER, line 157-206) whose property reads register per-FIELD deps in fieldDeps — `{todo.title}` subscribes only to field 'title'; reconcile fires notifyField(changedKey) (line 310-316) so only bindings reading the mutated field re-fire. Granularity is DEPTH-1: `{todo.meta.tags}` registers a dep on 'meta' only; deeper reads are plain untracked property access. as-mode contexts are key-sealed after seed (sealKeysAfterReplace, line 49-58 comment + 322). Spread mode ({#each todos} with fields merged flat): setKey per changed field + notifyKey('this') for whole-item readers (each.js:476-481); unsealed, so late-added doc fields propagate via keySetVersion. Helper calls unwrap the item proxy via the UNWRAP symbol (/home/jack/semantic/next/packages/renderer/src/expression-evaluator.js:243-260, /home/jack/semantic/next/packages/renderer/src/helpers.js:26-34), registering a BARE_ITEM_DEP that notifyField also fires (reactive-context.js:107,161-169,314-315) — a binding passing the whole doc to a helper re-fires on ANY field change. Subtemplate reactiveData / snippet args use a different mechanism: buildArgsRecord (/home/jack/semantic/next/packages/renderer/src/engines/native/blocks/template.js:117-174) builds a flat record with native getter descriptors per declared key; each getter calls lookupExpressionValue at read time, so source-signal deps register directly on the reading binding's own Reaction — per-key isolation is structural with no intermediate dep layer. Data shape that benefits: documents with flat top-level fields, stable field sets, stable unique ids, and changed-field writes that replace top-level field references.

### {#async} block (only async template primitive)

/home/jack/semantic/next/packages/renderer/src/engines/native/blocks/async.js:109-148. Three states: sync value → render content immediately; pending promise → render loadingContent (or re-show last resolved value if no loadingContent, line 68-72); resolved → render content with data context from createSuccessDataContext (line 26-41: `as` → {[as]: value}, destructured parts+rest, or {this: value}); rejected → render errorContent (or nothing). Stale-promise protection via a generation counter (line 50, 76, 81): each re-evaluation bumps self.generation; late .then/.catch from older promises bail. The block's update() re-runs whenever signal deps inside the expression change, producing a NEW promise each time; every resolution does region.setContent(fragment) — a wholesale re-render of the state content with a fresh child scope (line 52-61), no keyed reuse at the async boundary. Sync throws route to the error hook only when errorContent exists (shouldRecover, line 116). Not usable in raw-text contexts (no evaluateText, line 144-147). For a live-query DB: {#async} fits one-shot fetches; continuously-updating queries should resolve into a Signal that feeds {#each} directly, not a promise.

### Per-expression Reactions and deep-field update path

Text expressions: defineValueBlock wires one Reaction per {expression} marker (/home/jack/semantic/next/packages/renderer/src/engines/native/define-block.js:311-391); re-fire recomputes the expression and writes a single text node (commitText `anchor.data = value`, line 257-263) or swaps parsed nodes for unsafeHTML (line 266-297). Attribute expressions: one Reaction per attribute via bindAttribute (/home/jack/semantic/next/packages/renderer/src/engines/native/attribute-binding.js:22-129), with setAttribute dedup against current value (line 86-89) and property sync for checked/selected/value (line 90-101). Dep registration during evaluation: lookupTokenValue / getDeepDataValue unwrap Signals at any path segment via .get() (/home/jack/semantic/next/packages/renderer/src/expression-evaluator.js:283-291, 327-352), so `{doc.profile.name}` where doc is a Signal subscribes the expression's Reaction to the WHOLE doc Signal — any notify on it re-runs every Reaction that read it, but each re-run is just one expression evaluation + one DOM write. Inside as-mode each items the item proxy narrows this to per-FIELD. Scheduling: Dependency.changed → Reaction.invalidate → Scheduler set (deduped per Reaction) → microtask flush (/home/jack/semantic/next/packages/reactivity/src/dependency.js:28-43, /home/jack/semantic/next/packages/reactivity/src/scheduler.js:12-81) — N field notifies to one Reaction in a tick coalesce to one re-run; deps are re-tracked from scratch each run (/home/jack/semantic/next/packages/reactivity/src/reaction.js:83-87). Reactions auto-stop when their anchor node disconnects (/home/jack/semantic/next/packages/renderer/src/engines/native/reaction-scope.js:19-28).

### Data context construction (component layer)

Flat namespace: Template.getDataContext() = extend({}, this.data, this.state, this.instance) (/home/jack/semantic/next/packages/templating/src/template.js:374-376) — settings, per-key state Signals (created from defaultState in createReactiveState, template.js:147-175), and createComponent return values merge into one object; settings overlay as Signals last (overlaySettingsSignals, template.js:380-417). Web component data: base.getData() spreads getSettings() + darkMode getter + uiClasses (/home/jack/semantic/next/packages/component/src/engines/native/base.js:294-316). Signals placed anywhere in this context are auto-unwrapped and dep-tracked by the evaluator. Subtemplate coarse path: a renderer with receivesData=true makes EVERY expression depend on renderer.dataDep (/home/jack/semantic/next/packages/renderer/src/engines/native/renderer.js:241-246); plain (non-reactiveData) data context replacement triggers bumpDataVersion → all expressions in that subtemplate re-fire (renderer.js:609-613, template.js:807-812). reactiveData avoids this via the lazy-getter record.

### {#rerender} / {#guard} and {#if} blocks (coarse-region semantics)

{#rerender expr} re-renders its whole content (fresh child scope + region.setContent) when any signal read by expr changes; {#guard key} gates re-render behind deep-equality of the keyed value (/home/jack/semantic/next/packages/renderer/src/engines/native/blocks/rerender.js:14-65). {#if} computes the matched branch AST; bag.place dedups on AST reference so re-fires with the same winning branch are no-ops, but a branch flip rebuilds the branch content wholesale — no DOM reuse across branches (/home/jack/semantic/next/packages/renderer/src/engines/native/blocks/conditional.js:25-93, define-block.js place at 133).

## Integration points
- Expose each live query result as a Signal holding the documents array, placed in component state or data context (e.g. defaultState or createComponent return) — the evaluator auto-unwraps Signals at /home/jack/semantic/next/packages/renderer/src/expression-evaluator.js:283-291 and {#each query} reads it via lookupExpression at /home/jack/semantic/next/packages/renderer/src/engines/native/blocks/each.js:512-517. Any object answering instanceof Signal works (IS_SIGNAL symbol protocol, /home/jack/semantic/next/packages/reactivity/src/signal.js:19-24), so a DB cursor could subclass or duck-type Signal.
- Give documents stable unique ids in one of the four fields Signal.id resolves (id, _id, hash, key — /home/jack/semantic/next/packages/reactivity/src/signal.js:29). Or override Signal.id (class static or per-signal option, signal.js:32-39) with the DB's primary-key accessor. This is what makes reconciliation keyed instead of positional.
- Optimal emit shape from the DB layer: re-emit the array with reference-preserved unchanged docs and fresh objects only for changed docs (or mutate in place + signal.notify()). Both land in reconcile's per-field diff (each.js:366-487) which fires only changed-field deps. Either works; preserving refs makes the unchanged-item cost one ref-compare per field (each.js:465-485).
- For nested doc changes, replace the top-level field reference (doc.meta = {...doc.meta, x}) — the snapshot diff and the per-FIELD dep system are both depth-1 (each.js:61-73, reactive-context.js:174-181). Immutable-style updates at field level are exactly the granularity rewarded; deeper immutability buys nothing.
- Targeted single-doc writes can go through existing Signal helpers — setItemProperty(id, prop, value), replaceItem(id, doc), removeItem(id), toggleItemProperty (signal.js:281-347 — id-based, uses getItemIndex linear scan). A DB layer can call these on its backing signal for point updates without re-emitting the array.
- Per-signal options at construction (signal.js:32-39): pass a cheap custom equality (e.g. query-result version counter) to skip the default deep isEqual on large array set() calls, or safety:'none' to always notify. Do NOT use safety:'clone' for query results — it forces the ref-changed reconcile path every pass (each.js:377-381).
- Feed per-doc detail views via subtemplate reactiveData or snippet args with one key per field/expression ({>docCard reactiveData={title: 'doc.title'}}), which compiles to per-key lazy getters (template.js block, /home/jack/semantic/next/packages/renderer/src/engines/native/blocks/template.js:117-174) — bindings inside subscribe directly to source signals. Avoid the blob data={...} form, which routes through bumpDataVersion and re-fires every expression in the subtemplate (renderer.js:241-246, 609-613).
- {#async dbQuery()} is suitable only for one-shot fetch promises (each dependency change creates a new promise and a wholesale region re-render on resolve, async.js:47-93). A live-query API should hand templates a Signal, optionally with an {#async} wrapper around only the initial-load promise.
- Batching: Scheduler coalesces invalidations per microtask (scheduler.js:26-81) and per-Reaction (pendingReactions is a Set), so a DB layer may write many field/doc updates synchronously in one tick and pay one re-run per affected Reaction — no manual batching API needed.

## Gotchas
- Field diffing is shallow (depth-1). In-place mutation of a nested object (doc.meta.count++) without replacing doc.meta is invisible: refreshSnapshotAndDetect compares snapshot[key] !== item[key] by reference (each.js:61-73), and item-proxy reads only register deps on the first path segment (reactive-context.js:174-181). The binding will not re-fire even though the each Reaction re-ran.
- Default Signal.set equality is DEEP isEqual (signal.js:27, utils/equality.js:15). Re-emitting a large unchanged query result costs a full deep compare per emit; a deep-equal-but-new array never notifies. Array helpers (push/splice/...) skip equality entirely and always notify.
- Objects without id/_id/hash/key fall back to positional-index keys (shared/each.js:21), silently degrading to index-keyed reconciliation (insert-at-head rewrites every row's data). Duplicate ids are not deduped in reconcile and will corrupt the head/tail walk — uniqueness is the DB layer's contract.
- Passing the whole item to a helper ({formatDoc todo}) unwraps the item proxy and registers the BARE_ITEM_DEP (reactive-context.js:161-169), which notifyField fires on EVERY field change (line 314-315) — coarse per-item granularity. Same for spread-mode {this} readers via notifyKey('this') (each.js:481).
- Removed keys slip past the snapshot diff by design (each.js:58-60 comment): deleting a field from a doc (vs setting it undefined) does not fire that field's dep. DB layers should write undefined rather than delete.
- as-mode each contexts are key-sealed after seeding (reactive-context.js:49-58, 322): the {[as], index} wrapper shape is fixed. Doc fields themselves can appear later (field deps are lazy), but in spread mode late-added fields rely on the unsealed keySetVersion channel — stable doc shapes are the fast path in both modes.
- safety:'clone' signals make every reconcile take the ref-changed path (fresh refs per read, each.js:377-381). Works correctly via key matching + snapshot diff, but never hits the cheap same-ref branch. Keep query-result signals at the default safety:'reference'.
- A Signal read through a dotted path ({doc.profile.name} where doc is a top-level Signal) subscribes to the WHOLE signal (expression-evaluator.js:339-351) — per-FIELD isolation exists only inside as-mode {#each} items and reactiveData getter records, not for arbitrary signals in the root context. The DOM cost per re-fire is still just one expression + one text/attribute write.
- Subtemplates without reactiveData are coarse: receivesData renderers hang every expression off renderer.dataDep (renderer.js:241-246); any data-context replacement (bumpDataVersion) re-fires all of them. This is documented as coarse-by-design (blocks/template.js header comment).
- {#async} re-renders its active state's content wholesale on every promise resolution (region.setContent with a fresh scope, async.js:52-61) and creates a new promise per dependency change — a per-tick-updating live query expressed as a promise would thrash. Generation counter only discards stale resolutions, it does not dedup work.
- Reactions flush on a microtask and auto-stop when their anchor disconnects only on their NEXT invalidation (reaction-scope.js:21-24) — detached-but-subscribed Reactions can run once more after removal; scope disposal on record/region teardown is what actually severs deps eagerly.
- Object (non-array) iteration ({#each obj}) wraps entries in fresh {key, value} objects per pass (arrayFromObject, each.js:512-517) and keys by property name; per-FIELD isolation applies to the unwrapped value only in as-mode (each.js:439-460). Arrays of docs are the optimized shape.
