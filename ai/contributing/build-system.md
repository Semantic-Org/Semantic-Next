# Build System Reference

> **Skill:** `sui:build-system`
> **Purpose:** Understand the build pipeline so you can modify build scripts, add components, or debug build failures

---

## Two-System Architecture

The monorepo builds two fundamentally different things:

| System | Location | What it produces | Key trait |
|--------|----------|-----------------|-----------|
| **Packages** | `packages/*` | Standalone JS libraries (`@semantic-ui/reactivity`, etc.) | Pure JS, no CSS, usable in any framework |
| **Core** | `src/` (root) | Web component framework (`@semantic-ui/core`) | CSS inlined into Shadow DOM, multi-stage build |

```
@semantic-ui/core
    depends on
@semantic-ui/component, @semantic-ui/query, @semantic-ui/specs
    which depend on
@semantic-ui/reactivity, @semantic-ui/templating, @semantic-ui/renderer, @semantic-ui/utils
```

Packages can be used standalone without core. Core requires the packages.

---

## Build Order

Wireit enforces this sequence:

```
1. build:packages      (8 packages in parallel)
2. build:ui-deps       (CSS bundles + spec generation)
3. build:ui-components (individual component dist files + page CSS)
4. build:ui-framework  (aggregated semantic-ui.js/css)
5. build:specs         (specs.js + component-specs.js to dist/)
```

Why this order matters:

```js
// Step 2 generates these files that step 3 needs:
import styles from './css/button-bundle.css';     // generated by build-ui-deps
import spec from './specs/button.component.js';    // generated by build-ui-deps
```

If you bypass wireit and run builds out of order, you get missing-module errors.

## Build Commands

| Command | What it does |
|---------|-------------|
| `npm run build` | Full build (packages + UI + specs + framework) |
| `npm run build:ui` | UI only (deps + components + specs + icons + framework) |
| `npm run build:ui-deps` | CSS bundles + spec generation only |
| `npm run build:packages` | All 8 packages in parallel |
| `npm run dev` | Watch mode + Astro docs dev server |
| `npm run watch` | Watch UI deps + framework + icons |

Single package build: `cd packages/reactivity && npm run build`

Each package's wireit `build` runs three sub-tasks in parallel: `build:esm`, `build:bundle`, `build:cdn` — all calling scripts in `internal-packages/scripts/src/`.

## Three Distribution Formats

Every build produces three variants:

| Format | Script | Output dir | Dependencies | Use case |
|--------|--------|-----------|-------------|----------|
| **ESM** | `build-esm.js` | `dist/` | Externalized | Bundlers (Vite, Webpack) |
| **Bundle** | `build-bundle.js` | `dist/bundle/` | Included | Direct `<script type="module">` |
| **CDN** | `build-cdn.js` | `dist/cdn/` | Rewritten to URLs | Import maps, no build step |

CDN format uses the `esbuild-resolve-bare-imports` plugin to rewrite bare imports to jsDelivr URLs:
```js
// input
import { Signal } from '@semantic-ui/reactivity';
// output (version from package.json dependencies)
import { Signal } from 'https://cdn.jsdelivr.net/npm/@semantic-ui/reactivity@0.18.0/dist/cdn/index.min.js';
```

Each format builds both minified and unminified (e.g., `dist/semantic-ui.js` + `dist/semantic-ui.min.js`).

## build-ui-deps (Critical Script)

This is the most important script to understand. It generates internal dependencies that web components import at runtime.

### CSS Bundling

**Problem:** Components load CSS as text via esbuild's `{ '.css': 'text' }` loader. This loader does **not** follow `@import` — they arrive as literal strings, breaking the stylesheet.

**Solution:** Pre-bundle CSS with esbuild's CSS loader (which follows `@import`), output as `*-bundle.css`:

```
src/primitives/button/css/button.css          (source, has @import)
src/primitives/button/css/button-bundle.css   (generated, @imports inlined)
```

Components import the bundle:
```js
import styles from './css/button-bundle.css';
```

Generated bundles include a banner: `---DO NOT EDIT THIS FILE DIRECTLY---`

### Spec Generation

Specs are authored as `.spec.js` and generate multiple output files:

```
button.spec.js       (authored)  ->  button.spec.json       (JSON snapshot for tooling/LLMs)
                                 ->  button.component.js    (processed via SpecReader.getWebComponentSpec())
                                 ->  buttons.component.js   (plural variant, if supportsPlural)
```

Why JS as source of truth:
- Comments allowed
- Can import helpers (`import { COLOR_OPTIONS } from '@semantic-ui/specs'`)
- Trailing commas, computed values from helper functions

`validateSpec()` ensures the final spec is JSON-serializable:
```js
// not allowed in spec output
export default {
  states: { getValue: () => 'active' }  // function
};
// allowed
import { getStates } from '@semantic-ui/specs';
export default {
  states: getStates(['active', 'disabled'])  // returns pure array
};
```

**All generated files are committed to the repo** because consumers using the `"import"` export condition get source files directly — they need `-bundle.css` and `.component.js` to exist without running a build.

## Export Conditions

### Packages (e.g., `@semantic-ui/reactivity`)

```json
{
  ".": {
    "types": "./types/index.d.ts",
    "import": "./src/index.js",
    "browser": "./dist/bundle/index.min.js",
    "importmap": "./dist/cdn/index.min.js"
  }
}
```

`"import"` points to **source** (not dist) — enables tree-shaking in bundlers.

### Core (`@semantic-ui/core`)

```json
{
  ".": {
    "types": "./types/index.d.ts",
    "import": "./dist/semantic-ui.js",
    "browser": "./dist/cdn/semantic-ui.min.js",
    "bundled": "./dist/semantic-ui.min.js",
    "default": "./dist/semantic-ui.js"
  }
}
```

`"import"` points to **dist** for the full framework (pre-built to reduce consumer build time), but individual primitives point to **source**:

```json
{
  "./button": {
    "import": "./src/primitives/button/index.js",
    "browser": "./dist/cdn/button.min.js",
    "bundled": "./dist/bundle/button.min.js",
    "default": "./src/primitives/button/index.js"
  }
}
```

CSS exports always point to source — the consumer's build pipeline processes them.

## Watch Mode

```js
// watch.js defaults
watchDeps: true,        // CSS bundles + specs — required for dev
watchFramework: true,   // aggregated framework build — playground uses this
watchComponents: false  // individual component dist — rarely needed
```

The `watch` wireit task also runs `watch:icons` (via `packages/specs`).

Edit flow: `button.css` changes -> `build-ui-deps` regenerates `button-bundle.css` -> `build-ui-framework` rebuilds `semantic-ui.js` -> docs hot-reload.

Spec watch uses cache-busting (`import(url + '?t=' + Date.now())`) to force JS module reload on change.

## Build Config

Located in `internal-packages/scripts/src/lib/config.js`:

```js
TARGET_BROWSERS = ['chrome130', 'edge130', 'firefox130', 'safari17', 'ios17']

// JS builds: .css as text (Shadow DOM inlining), .html as text, .svg/.png as file
// CSS builds: .css as css (follows @import), .svg as dataurl, .png as file
```

The `build()` wrapper in `lib/build.js` auto-reads `package.json` to generate license banners, discover entry points, externalize dependencies (ESM), and configure output paths.

| What | Where |
|------|-------|
| Build scripts | `internal-packages/scripts/src/` |

| Generated component specs | `src/primitives/*/specs/*.component.js` |
| Wireit config | root `package.json` -> `wireit` |
| Export conditions | root `package.json` -> `exports` |

## Common Errors

| Error | Fix |
|-------|-----|
| `Cannot find module './css/button-bundle.css'` | Run `npm run build:ui-deps` |
| `Cannot find module './specs/button.component.js'` | Run `npm run build:ui-deps` |
| Spec validation failed | Spec output must be pure data — no functions, Date, RegExp. Imported helpers OK if they return serializable values. |
| CDN URL incorrect | Clear `.cache/` directory and rebuild |
| Watch not detecting spec changes | Cache busting handles this; restart watch if stuck |

## Quick Reference

```
Build everything:          npm run build
Build UI only:             npm run build:ui
Build one package:         cd packages/[name] && npm run build
Regenerate CSS/specs:      npm run build:ui-deps
Dev mode:                  npm run dev

Source (you edit):         src/primitives/*/specs/*.spec.js
                           src/primitives/*/css/*.css

Generated (don't edit):   src/primitives/*/css/*-bundle.css
                           src/primitives/*/specs/*.spec.json
                           src/primitives/*/specs/*.component.js
```
