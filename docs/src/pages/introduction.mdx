Semantic UI is an ecosystem for building user interfaces entirely with **standard Web Components**. Components built with or provided by Semantic UI work natively in modern browsers and can be integrated into applications using frameworks like React, Vue, Angular, or others that support Web Components.

Semantic UI offers two primary ways to build:

* **Use Pre-built Components:** Use a library of common UI component primitives like [buttons](/ui/button), [menus](/ui/menu), and [inputs](/ui/input) to build layouts quickly.
* **Create Custom Components:** Use the [component authoring framework](/component) to build your own custom, reactive Web Components from scratch.


The authoring framework provides tools for core component development tasks often requiring manual setup or external libraries when using Web Components directly. This includes:

* [Signals-based reactivity](/reactivity)
* [Declarative templating](/templates)
* [DOM querying tailored for Shadow DOM](/query)
* [Scoped styling and theming](/components/styling)
* [Event handling tools](/components/events)
* [Keybinding management](/components/keys)

## Using UI Components

The `@semantic-ui/core` package provides a collection of essential, pre-built UI components for typical application needs. These are distributed as standard Web Components.

> **Modular Architecture**
> Each core library (`@semantic-ui/query`, `@semantic-ui/reactivity`, `@semantic-ui/templating`, `@semantic-ui/utils`) is independent and can be used standalone. For example, `@semantic-ui/query` can serve as a jQuery alternative, or `@semantic-ui/reactivity` can be used solely for its signals implementation. This allows for incremental adoption or use of specific libraries without the full component framework.
