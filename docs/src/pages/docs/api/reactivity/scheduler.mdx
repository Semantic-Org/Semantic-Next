The batching engine behind reactivity. Signals queue their dependents here, and `Scheduler` drains them on a microtask. Most code reaches it through the free functions on [Flushing](/docs/api/reactivity/flushing) rather than the class.

> [!info]
> [`flush`](/docs/api/reactivity/flushing#flush), [`scheduleFlush`](/docs/api/reactivity/flushing#scheduleflush), [`afterFlush`](/docs/api/reactivity/flushing#afterflush), and [`getSource`](/docs/api/reactivity/debugging#getsource) are exported from `@semantic-ui/reactivity` as standalone functions bound to these statics. Import those instead of touching `Scheduler` directly.

## Class Statics

`Scheduler` exposes its queues and flags as statics. They are read by the reactivity internals, treat them as observable state, not as a public mutation surface.

### current

```javascript
Scheduler.current;
```

The reaction currently executing, or `null` outside a flush. Prefer [`currentReaction()`](/docs/api/reactivity/controls#currentreaction) to read it.

#### Returns

A [`Reaction`](/docs/api/reactivity/reaction) or `null`.

### pendingReactions

```javascript
Scheduler.pendingReactions;
```

The `Set` of reactions queued for the next flush.

#### Returns

`Set<Reaction>`.

### afterFlushCallbacks

```javascript
Scheduler.afterFlushCallbacks;
```

The array of callbacks queued to run after the next flush drains.

#### Returns

`Array<() => void>`.

### isFlushScheduled

```javascript
Scheduler.isFlushScheduled;
```

Whether a flush is already queued on the microtask, used to keep `scheduleFlush` idempotent.

#### Returns

`boolean`.

### isFlushing

```javascript
Scheduler.isFlushing;
```

Whether a flush is currently draining.

#### Returns

`boolean`.

### maxFlushIterations

```javascript
Scheduler.maxFlushIterations;
```

The pass cap before `flush` declares a reactive cycle and clears its queues. Defaults to `100`.

#### Returns

`number`.

### scheduleReaction

```javascript
Scheduler.scheduleReaction(reaction);
```

Queues a reaction for the next flush and schedules one. Called by signals when a dependency changes, not part of the application surface.

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| reaction | [`Reaction`](/docs/api/reactivity/reaction) | The reaction to queue |
