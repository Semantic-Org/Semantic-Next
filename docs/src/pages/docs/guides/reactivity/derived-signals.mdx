A derived signal computes its value from other signals and caches it, recomputing only when an input it actually read changes. Three shapes cover the common cases.

## derive — one source

`signal.derive(fn)` transforms a single signal. The result tracks its source and recomputes when that source changes.

```javascript
const items = signal(['apple', 'banana', 'cherry']);
const count = items.derive(list => list.length);

count.get(); // 3
items.push('date');
count.get(); // 4
```

## computed — many sources

`computed(fn)` reads several signals in its body and recomputes when any of them change.

```javascript
const price = signal(10);
const quantity = signal(3);
const total = computed(() => price.get() * quantity.get());

total.get(); // 30
quantity.set(4);
total.get(); // 40
```

<PlaygroundExample id="reactive-computed" />

> `derive` hands you the source value, `computed` reads its own signals. Use `derive` for a one-to-one transform, `computed` when the value combines several.

## match — one of many

`match(source)` returns a selector for the "highlight one of N" pattern: a selected row, the active tab, the current route. Reading a key inside a reaction subscribes only that key, so changing the source re-runs the keys whose state flipped, not all N.

```javascript
const selected = signal('inbox');
const isSelected = match(selected);

isSelected('inbox'); // true
isSelected('drafts'); // false

selected.set('drafts'); // re-runs only 'inbox' and 'drafts'
```

## Teardown

Each of these runs a reaction internally. Inside a component it stops automatically with the component. Created standalone, it self-stops once nothing references it, or call `.stop()` to tear it down immediately.
