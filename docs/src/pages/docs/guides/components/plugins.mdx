Plugins let you share behavior across components — adding custom options to `defineComponent`, helpers to templates, and utilities to component callbacks.

> See the [Component Plugins API Reference](/docs/api/component/plugins) for method signatures and options.

## Using Plugins

### Adding a Plugin

Call `addPlugin` once in your application setup to enable a plugin and pass any app-wide settings.

```javascript {5-8}
import { addPlugin } from '@semantic-ui/component';
import { I18n } from './i18n-plugin.js';
import { strings } from './locales.js';

addPlugin(I18n, {
  locale: 'en',
  strings,
});
```

### Using in a Component

Once added, a plugin can be configured directly on `defineComponent` under its name (`i18n`), and any template helpers or callback arguments it provides are ready to use.

```javascript {2,9}
const events = {
  'click ui-button'({ i18n, data }) {
    i18n.setLocale(data.locale);
  },
};

defineComponent({
  tagName: 'checkout-summary',
  i18n: 'checkout', // uses checkout translations for this component
  template: `<h3>{t 'title'}</h3>`,
  events,
});
```

You can also call a plugin's methods directly from the DOM element at `el[namespace]`:

```javascript
document.querySelector('checkout-summary').i18n.setLocale('es');
```

## Extending Callbacks

### Shared Parameters

If you just want to make shared functions or services available inside component callbacks (`createComponent`, `events`, `keys`, and lifecycle hooks) without writing a full plugin, use `extendParams`:

```javascript {4-6}
import { extendParams } from '@semantic-ui/component';

// can now be destructured in any component callback
extendParams({
  setCurrency: (code) => currency.set(code),
  formatPrice: (usd) => format(usd, currency.get()),
});
```

### Per-Component Parameters

If the helper needs context from the component itself — like its DOM element `el` or `state` — pass a function to `extendParams`:

```javascript {1-3}
extendParams(({ el }) => ({
  track: (event, data) => analytics.send(el?.tagName, event, data),
}));
```

## Authoring Plugins

### Adding a Component Option

Use `registerPlugin` to create a plugin. Its `namespace` becomes a new option you can pass to `defineComponent`:

```javascript {3}
defineComponent({
  tagName: 'sticky-note',
  persist: ['note'], // saves state.note to localStorage
  defaultState: { note: '' },
});
```

Whatever value a component passes to `persist` is given to your plugin callbacks as `config`. Setting `appliesTo: 'configured'` tells Semantic UI to only run the plugin on components that actually specify `persist`:

### Exposing Methods & Helpers

A plugin can also provide methods and template helpers to components:

* **`createPlugin`** defines the plugin's methods (accessible as `self` inside the plugin and on the DOM element as `el[namespace]`), just like `createComponent` does for a component.
* **`lifecycleParams`** returns the properties you want to add to component callbacks (`createComponent`, `events`, `onCreated`, etc.).
* **`templateHelpers`** returns the helper functions you want to make available inside component HTML templates.

```javascript {10-16}
const createPlugin = ({ settings }) => ({
  t(key) {
    const { locale, prefix, strings } = settings;
    const path = prefix ? `${prefix}.${key}` : key;
    return get(strings[locale], path) ?? key;
  },
});

// adds { t, i18n } to component callbacks
const lifecycleParams = ({ self }) => ({
  t: self.t,
  i18n: self,
});

// adds {t 'key'} to component templates
const templateHelpers = ({ self }) => ({
  t: self.t,
});
```

### Plugin Settings

Plugin settings behave identically to [component settings](/docs/guides/components/settings) and specify settings available across all downstream components.

If you want to resolve runtime settings using custom logic — for example, letting a component pass a shorthand like `i18n: 'checkout'` — you can specify a `resolveSettings` function that returns the resolved settings from a user's `config`:

```javascript {8-13}
const defaultSettings = {
  locale: 'en',
  strings: {},
  prefix: '',
};

// allow shorthand config like i18n: 'checkout'
const resolveSettings = ({ settings, config }) => {
  if (isString(config)) {
    return { ...settings, prefix: config };
  }
  return settings;
};
```

Settings customized on a single component (like `prefix: 'checkout'`) apply only to that component, while shared settings (like `locale`) stay in sync across every component on the page.
