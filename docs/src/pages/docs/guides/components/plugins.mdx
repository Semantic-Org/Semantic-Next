Plugins in Semantic UI let you extend [`defineComponent`](/docs/guides/components/create#defining-components) directly to give new functionality like [i18n](#usage-example), [state persistence](/examples/persist-plugin), or any other features that enhance what a component can do.

With plugins you can do things like:
* **Enhance Components** - Add [new config options](#plugin-settings) to `defineComponent` that get passed to your code.
* **Add Arguments to Lifecycle Callbacks** - Add new top-level lifecycle arguments available to users [callback arguments](/docs/guides/components/lifecycle#callback-arguments)
* **Add Helpers** - Add custom [template helpers](/docs/guides/templates/helpers)
* **Run Code on Lifecycle** - Run code on component create, render, destroy, or other lifecycle events

> See the [Component Plugins API Reference](/docs/api/component/plugins) for method signatures and options.

## Using Plugins

### Adding a Plugin


To enable a plugin on your app call [`addPlugin`](/docs/api/component/plugins#addplugin) once in your application setup to enable a plugin and configure its application-wide [settings](/docs/guides/components/settings).

Third party plugins can be used from NPM packages by calling `addPlugin`

```javascript {4} title="Third Party Plugins"
import { addPlugin } from '@semantic-ui/component';
import { ContainerQueryPlugin } from '@third-party/container-plugin'

addPlugin(ContainerQueryPlugin, { config: 'setting'});
```

You can also [write your own plugins](#authoring-plugins) and import them locally

```javascript {5-8} title="Local Plugins"
import { addPlugin } from '@semantic-ui/component';
import { I18n } from './i18n-plugin.js';
import { strings } from './locales.js';

addPlugin(I18n, {
  locale: 'en',
  strings,
});
```

### Using Plugins in Components

Plugins can be configured directly from `defineComponent` by passing a key with the plugin's name

```javascript {6-8}
defineComponent({
  tagName: 'my-component',
  createComponent,
  onCreated,
  onDestroyed,
  i18n: {
    locale: 'en',
  },
});
```

Some plugins might also expose new lifecycle arguments that you can access to interact with their APIs.

```javascript {3}
const events = {
  'click ui-button'({ i18n, data }) {
    i18n.setLocale(data.locale);
  },
};
```
Or custom template helpers that are enabled when you activate the plugin
```sui title='template.html'
<h3>{t 'title'}</h3>
<p>{t 'description'}</p>
```

You can also access the plugin from the DOM from any component

```javascript
document.querySelector('my-component').pluginName.method();
```

## Authoring Plugins

### Registering Plugins

[`registerPlugin`](/docs/api/component/plugins#registerplugin) lets a component author define their plugin. See the [API Reference](/docs/api/component/plugins) for further details


```javascript
registerPlugin({
  namespace, // how its stored on el
  defaultSettings, // setting a user can write with defaults
  resolveSettings, // custom resolver for user settings
  createPlugin, // instance creation factory
  lifecycleParams, // args to add to lifecycle events
  templateHelpers, // obj of template helpers to add
  onCreated, // runs on component created
  onRendered, // runs on component rendered
  onDestroyed, // runs on component destroyed
  appliesTo, // determines which components plugin applies to
});
```

### Creating a Plugin

`createPlugin` like [`createComponent`](/docs/guides/components/instances#create-component) lets you create your plugin instance. This is used internally from any callback as `self` and lets you provide an external API for your plugin.

```javascript title="i18n-plugin.js"
const createPlugin = ({ settings }) => ({
  t(key) {
    const { locale, prefix, strings } = settings;
    const path = prefix ? `${prefix}.${key}` : key;
    return get(strings[locale], path) ?? key;
  },
  setLocale(locale) {
    settings.locale = locale;
  },
});
```

#### DOM Access

Your plugin instance can be accessed [outside the component](/docs/guides/components/instances#from-dom) from the DOM

```javascript title="Query"
$('checkout-summary').el().i18n.setLocale('es');
```

```javascript title="Native"
document.querySelector('checkout-summary').i18n.setLocale('es');
```

### Specifying When Plugin Applies

Your plugin can use `appliesTo` to specify when it should be applied. This permits keywords or a function that runs once for each component to determine if its applicable


#### Scoping Values

| Value                     | Behavior                                                                                  |
|---------------------------|-------------------------------------------------------------------------------------------|
| `'components'` (default)  | Top-level web components, plus subtemplates that explicitly set `[namespace]`             |
| `'all'` or `'templates'`  | Every web component and subtemplate                                                       |
| `'configured'`            | Only components or subtemplates that pass `[namespace]` in `defineComponent`              |
| `tagName` or `tagName[]`    | Components matching the given `tagName`                       |
| `templateName` or `templateName[]`    | Components matching the given `templateName`                                    |

#### Custom Applies To

You can use a callback for `appliesTo` to determine at run-time whether a plugin should apply

```js title='Plugin' {6-9}
registerPlugin({
  name: 'currencyLocale',
  defaultSettings: {
    language: 'en',
  },
  // apply if a user has `currency` in their own settings
  appliesTo({ componentSettings }) {
    return Boolean(componentSettings?.currency);
  },
  resolveSettings({ self, componentSettings }) {
    return {
      language: self.getLanguage(componentSettings.currency),
    };
  },
});
```

```js title="User (Plugin Used)" {3-6}
defineComponent({
  tagName: 'money-input',
  // component has currency
  defaultSettings: {
    currency: 'usd',
  },
});
```

```js title="User (Plugin Not Used)" {3-6}
defineComponent({
  tagName: 'text-input',
  // not related to currency
  defaultSettings: {
    value: '',
  },
});
```

### Callback Parameters

`lifecycleParams` lets you pass your plugin's methods or properties to component's [callback arguments](/docs/guides/components/lifecycle#callback-arguments) received by lifecycle events like [`createComponent`](/docs/guides/components/instances#create-component), [event handlers](/docs/guides/components/events), [keybindings](/docs/guides/components/keys), and [lifecycle callbacks](/docs/guides/components/lifecycle)

> [`extendParams`](#extending-callbacks) (see below) can be used by itself to pass through simple functions or helpers without authoring a full plugin.

```javascript title="Plugin" {3}
const lifecycleParams = ({ self }) => ({
  t: self.t,
  i18n: self, // expose whole plugin to user
});
```

Components can then destructure `{ t, i18n }` directly inside any callback alongside standard arguments like `state` and `data`:

```javascript title="User" {3}
const events = {
  'click ui-button'({ i18n, data }) {
    i18n.setLocale(data.locale); // call a plugin API
  },
};
```

### Template Helpers

Use `templateHelpers` to register [custom template helpers](/docs/guides/templates/helpers#custom-helpers) that components can call inside their [templates](/docs/guides/templates/expressions).

Unlike global helpers registered with [`registerHelpers`](/docs/guides/templates/helpers#multiple-helper-registration), passing a function to `templateHelpers` scopes the helpers to each component instance so `{t 'title'}` automatically resolves against that component's own plugin `settings`:

```javascript title="Plugin"
const templateHelpers = ({ self }) => ({
  t: self.t,
});
```

```sui title="User Template"
<h3>{t 'title'}</h3>
<p>{t 'subtotal'}</p>
```

### Plugin Settings

Plugin settings let you specify settings that a downstream user can set on their component.

```javascript title='Plugin' {3-5}
registerPlugin({
  name: 'i18n',
  defaultSettings: {
    lang: 'en',
  },
});
```

```javascript title='User' {2-4}
defineComponent({
  i18n: {
    lang: 'es', // component uses a diff lang
  },
  tagName,
  createComponent,
  // rest
});
```

### Advanced Plugin Settings

If you need to customize how a user's settings are applied to your plugin use [`resolveSettings`](/docs/api/component/plugins#options).


```javascript title='User' {2}
defineComponent({
  i18n: 'es', // shorthand use
  tagName,
  createComponent,
  // rest
});
```

```javascript title='Plugin' {6-11}
registerPlugin({
  name: 'i18n',
  defaultSettings: {
    lang: 'en',
  },
  // shorthand supported
  resolveSettings({ settings, config }) {
    if (isString(config)) {
      settings.lang = config;
    }
  },
});
```

## Extending Callbacks

If you want to just provide additional component lifecycle params without writing a full plugin you can use `extendParams`.


```javascript {3} title="Plugin"
import { extendParams } from '@semantic-ui/component';
extendParams({
  setCurrency: (code) => currency.set(code),
});
```

Users can then access those new params from any part of a component to call your plugins code.

```javascript title="User" {4}
defineComponent({
  events: {
    'click [data-currency]'({ setCurrency, data }) {
      setCurrency(data.currency);
    },
  },
});
```

### Per-Component Parameters

Parameters themselves can use a callback function to make their behavior vary depend on how its called.

This can be used to change behavior based on the DOM `el`, [`state`](/docs/guides/components/state), or [`settings`](/docs/guides/components/settings), or whatever else you can dream up.

```javascript
extendParams(({ el }) => ({
  track: (event, data) => analytics.send(el?.tagName, event, data),
}));
```
