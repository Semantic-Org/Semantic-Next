Component specs are declarative JSON contracts that define what a component can do - its attributes, variations, states, and behaviors. When used with `defineComponent`, specs automatically configure web component properties, enable all three HTML dialects, validate attributes, and generate documentation. Without a spec, components must manually define all properties and only support verbose syntax.

## Core Concepts

### Spec Structure

Every spec requires these fields

```json
{
  "uiType": "element",
  "name": "Button",
  "description": "A button indicates a possible user action",
  "tagName": "ui-button",
  "exportName": "UIButton"
}
```

### Types vs Variations

The key distinction in Semantic UI specs

- **Types**: Mutually exclusive behaviors (pick one)
- **Variations**: Stackable visual modifications (combine many)

```html
<!-- Types: Can only be primary OR secondary -->
<ui-button primary>Save</ui-button>
<ui-button secondary>Cancel</ui-button>

<!-- Variations: Can combine multiple -->
<ui-button large fluid red>Delete Account</ui-button>
```

## Component Definition

### Content

Define slots and content areas

```json
"content": [
  {
    "name": "Icon",
    "attribute": "icon",
    "slot": "icon",
    "description": "include an icon",
    "exampleCode": "<ui-button icon=\"save\">Save</ui-button>"
  }
]
```

Content supports both attribute and slot syntax.

### Types

Define mutually exclusive behaviors

```json
"types": [
  {
    "name": "Emphasis",
    "attribute": "emphasis",
    "description": "be emphasized in a layout",
    "options": [
      {
        "name": "Primary",
        "value": "primary",
        "description": "be emphasized as the first action"
      },
      {
        "name": "Secondary",
        "value": "secondary",
        "description": "be emphasized as a secondary option"
      }
    ]
  }
]
```

### States

Define runtime state changes

```json
"states": [
  {
    "name": "Hover",
    "attribute": "hover",
    "description": "be hovered"
  },
  {
    "name": "Disabled",
    "attribute": "disabled",
    "description": "have interactions disabled",
    "options": [
      {
        "name": "Disabled",
        "value": "disabled",
        "description": "disable interactions"
      },
      {
        "name": "Clickable Disabled",
        "value": "clickable-disabled",
        "description": "allow interactions but appear disabled"
      }
    ]
  }
]
```

### Variations

Define stackable visual modifications

```json
"variations": [
  {
    "name": "Size",
    "attribute": "size",
    "description": "vary in size",
    "options": [
      {"name": "Small", "value": "small", "description": "appear small"},
      {"name": "Large", "value": "large", "description": "appear larger than normal"}
    ]
  },
  {
    "name": "Fluid",
    "attribute": "fluid",
    "description": "take the width of its container"
  }
]
```

## Configuration

### Settings

Define configuration properties

```json
"settings": [
  {
    "name": "Href",
    "type": "string",
    "attribute": "href",
    "description": "link to a webpage"
  },
  {
    "name": "Debounced",
    "type": "boolean",
    "attribute": "debounced",
    "defaultValue": false,
    "description": "debounce input value changes"
  }
]
```

### Events

Define custom events

```json
"events": [
  {
    "eventName": "change",
    "description": "occurs after the value changes",
    "arguments": [
      {
        "name": "value",
        "description": "the updated value"
      }
    ]
  }
]
```

### Plural Components

Support component collections

```json
{
  "supportsPlural": true,
  "pluralName": "Buttons",
  "pluralTagName": "ui-buttons",
  "pluralExportName": "UIButtons",
  "pluralDescription": "Buttons can exist together as a group",

  "pluralSharedVariations": ["size", "color", "floated"],

  "pluralOnlyVariations": [
    {
      "name": "Equal Width",
      "attribute": "equal-width",
      "description": "have the same width for each button"
    }
  ]
}
```

Only share obvious visual variations (size, color). Not behavioral types (submit, reset).

## Writing Guidelines

### Description Format

Use imperative mood without the component name

```json
// Good
"description": "be emphasized"
"description": "appear small"
"description": "have interactions disabled"

// Bad
"description": "The button can be emphasized"
"description": "Makes the button appear small"
"description": "Button with disabled interactions"
```

### Usage Levels

Indicate feature commonality (1-5)

```json
{
  "name": "Size",
  "usageLevel": 1,  // Essential feature
  "description": "vary in size"
}

{
  "name": "Animated",
  "usageLevel": 3,  // Advanced feature
  "description": "animate to show hidden content"
}
```

- **1**: Essential features
- **2**: Common features
- **3**: Advanced features
- **4**: Specialized features
- **5**: Rare features

### Example Configuration

Provide defaults for documentation

```json
"examples": {
  "defaultAttributes": {
    "icon": "check-circle"  // Icons always need a glyph
  },
  "defaultContent": "Click Me"
}
```

### Standard Sizes

```json
"options": [
  {"name": "Mini", "value": "mini", "description": "appear extremely small"},
  {"name": "Tiny", "value": "tiny", "description": "appear very small"},
  {"name": "Small", "value": "small", "description": "appear small"},
  {"name": "Medium", "value": "medium", "description": "appear normal sized"},
  {"name": "Large", "value": "large", "description": "appear larger than normal"},
  {"name": "Big", "value": "big", "description": "appear much larger than normal"},
  {"name": "Huge", "value": "huge", "description": "appear very much larger than normal"},
  {"name": "Massive", "value": "massive", "description": "appear extremely larger than normal"}
]
```

### Standard Colors

```json
"options": [
  {"name": "Red", "value": "red", "description": "be red"},
  {"name": "Orange", "value": "orange", "description": "be orange"},
  {"name": "Yellow", "value": "yellow", "description": "be yellow"},
  {"name": "Green", "value": "green", "description": "be green"},
  {"name": "Blue", "value": "blue", "description": "be blue"},
  {"name": "Purple", "value": "purple", "description": "be purple"}
]
```

### Form Components

```json
"settings": [
  {"name": "Name", "type": "string", "attribute": "name"},
  {"name": "Value", "type": "string", "attribute": "value"},
  {"name": "Required", "type": "boolean", "attribute": "required", "defaultValue": false}
],
"events": [
  {"eventName": "change", "arguments": [{"name": "value"}]}
]
```

## Integration

### Using Specs with Components

Specs integrate directly with `defineComponent` to automatically configure web components

```javascript
import { defineComponent } from '@semantic-ui/component';
import alertSpec from './specs/alert-component.js';

export const UIAlert = defineComponent({
  tagName: 'ui-alert',
  componentSpec: alertSpec,  // Spec configures entire API

  // Only provide implementation
  template: `<div class="{ui} alert">{message}</div>`,
  css: `.alert { ... }`,
  createComponent: ({ self }) => ({
    dismiss() {
      self.dispatchEvent('dismiss');
    }
  })
});
```

The spec automatically provides
- Property definitions with correct types
- Support for all three dialects (standard, verbose, classic)
- Bidirectional attribute mapping via `optionAttributes`
- Default values for all settings
- Value validation against allowed options
- CSS class generation from attributes

**Important**: Specs are REQUIRED to support all three dialects. Without a spec, only the verbose dialect works.

### Build Process

After creating or modifying a spec

```bash
npm run build:ui-deps
```

This generates
- Component runtime metadata (`*-component.js`)
- Documentation structure

### Quick Reference

| Section | Purpose | Mutually Exclusive |
|---------|---------|-------------------|
| `types` | Core behaviors | Yes |
| `variations` | Visual modifications | No |
| `states` | Runtime changes | No |
| `settings` | Configuration | No |
| `content` | Slots/attributes | No |
| `events` | Custom events | No |

## Complete Example

```json
{
  "uiType": "element",
  "name": "Alert",
  "description": "An alert displays an important message",
  "tagName": "ui-alert",
  "exportName": "UIAlert",

  "content": [
    {
      "name": "Icon",
      "attribute": "icon",
      "slot": "icon",
      "description": "include an icon"
    }
  ],

  "types": [
    {
      "name": "Severity",
      "attribute": "severity",
      "description": "indicate message importance",
      "options": [
        {"name": "Info", "value": "info", "description": "be informational"},
        {"name": "Warning", "value": "warning", "description": "indicate a warning"},
        {"name": "Error", "value": "error", "description": "indicate an error"}
      ]
    }
  ],

  "states": [
    {
      "name": "Visible",
      "attribute": "visible",
      "description": "be visible"
    }
  ],

  "variations": [
    {
      "name": "Dismissible",
      "attribute": "dismissible",
      "description": "be dismissible by the user"
    }
  ],

  "settings": [
    {
      "name": "Auto Dismiss",
      "type": "number",
      "attribute": "auto-dismiss",
      "description": "automatically dismiss after milliseconds"
    }
  ],

  "events": [
    {
      "eventName": "dismiss",
      "description": "occurs when dismissed"
    }
  ]
}
```
