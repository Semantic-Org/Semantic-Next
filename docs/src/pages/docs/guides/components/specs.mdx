Component specs are declarative JSON contracts that define a component's API in a machine-readable format. All primitives in `@semantic-ui/core` use specs, but they're optional for custom components.

## What Specs Enable

Without specs, components must manually handle attribute mapping and only the verbose dialect works:

```javascript
// Without spec - manual attribute handling, limited dialect support
defineComponent({
  tagName: 'ui-button',
  defaultSettings: {
    primary: false,
    secondary: false,
    size: 'medium',
    // Must manually define every setting
  },
  createComponent: ({ settings }) => ({
    // Must manually handle attribute mapping
    isPrimary() {
      return settings.primary === 'true' || settings.primary === true;
    }
  }),
  // Only verbose syntax works: <ui-button primary="true">
});
```

With a spec, attribute mapping and dialect support are automatic:

```javascript
// With spec - automatic attribute mapping, all dialects work
import componentSpec from './specs/button-component.js';

defineComponent({
  tagName: 'ui-button',
  componentSpec,  // Handles all attribute mapping automatically
  template,
  css,
  // All three dialects work:
  // <ui-button primary>            (standard)
  // <ui-button primary="true">     (verbose)
  // <ui-button class="ui primary"> (classic)
});
```

> [!info] Why Specs Help with AI
> When AI assistants help you code, they need to know what's valid. Without specs, AI guesses - often suggesting invalid combinations like `primary secondary` on the same button. With specs, AI knows exactly which attributes exist, which combine, and which are mutually exclusive.

## When to Use a Spec

### Use Specs When

You want AI assistants to understand your components, need machine-readable API definitions for a design system, or want automatic support for all three HTML dialects. Specs are also essential for plural components that share variations and for enabling tooling like linters or documentation generators.

### Skip Specs When

You're building one-off internal components, prototyping with a rapidly evolving API, or creating simple components where the overhead isn't justified. If you don't need machine readability or dialect support, a spec may be unnecessary.


## Using Specs at Runtime

The `@semantic-ui/specs` package provides a `SpecReader` class that can load and process JSON specs at runtime.

```javascript
import { SpecReader } from '@semantic-ui/specs';
import { defineComponent } from '@semantic-ui/component';

// Load your spec at runtime
const specReader = new SpecReader();
const buttonSpec = await specReader.read('./specs/button.json');

// Get the processed component spec
const componentSpec = specReader.getWebComponentSpec();

// Use it with defineComponent
export const UIButton = defineComponent({
  tagName: 'ui-button',
  componentSpec,  // Spec configures entire API
  template,
  css,
  createComponent: ({ self, settings }) => ({
    performAction() {
      // Component logic here
    }
  })
});
```

The spec automatically provides property definitions with correct types, support for all three HTML dialects, bidirectional attribute mapping, default values, validation, and CSS class generation.

> [!warning]
> Specs are required to support all three dialects. Without a spec, only the verbose dialect works.

## Build-Time Integration

Runtime loading parses JSON on every page load. For production, process specs at build time to eliminate this overhead:

```javascript
// build-specs.js
import { SpecReader } from '@semantic-ui/specs';
import fs from 'fs/promises';
import path from 'path';

async function buildSpecs() {
  const specReader = new SpecReader();
  const specsDir = './src/specs';
  const outputDir = './src/generated';

  // Read all JSON specs
  const files = await fs.readdir(specsDir);
  const specFiles = files.filter(f => f.endsWith('.json'));

  for (const file of specFiles) {
    // Load and process spec
    const spec = await specReader.read(path.join(specsDir, file));
    const componentSpec = specReader.getWebComponentSpec();

    // Write generated JavaScript module
    const outputFile = file.replace('.json', '-component.js');
    const output = `export default ${JSON.stringify(componentSpec, null, 2)};`;

    await fs.writeFile(
      path.join(outputDir, outputFile),
      output
    );
  }
}

buildSpecs();
```

Then import the generated specs directly:

```javascript
import { defineComponent } from '@semantic-ui/component';
import buttonSpec from './generated/button-component.js';

export const UIButton = defineComponent({
  tagName: 'ui-button',
  componentSpec: buttonSpec,
  // ... implementation
});
```

This approach provides better performance by avoiding runtime JSON parsing, enables build-time validation, and allows tree-shaking of unused spec data.

> [!info]
> This is the approach Semantic UI uses internally for `@semantic-ui/core` components, ensuring optimal performance and validation.

## Spec Format

A minimal spec looks like this:

```json
{
  "uiType": "element",
  "name": "Button",
  "description": "A button indicates a possible user action",
  "tagName": "ui-button",
  "exportName": "UIButton",
  "variations": [
    {
      "name": "Primary",
      "attribute": "primary",
      "description": "be emphasized"
    }
  ]
}
```

### Required Fields

Every spec must define these core properties:
- `uiType` - Always "element" for components
- `name` - Display name for documentation
- `description` - What the component does
- `tagName` - HTML tag name (must include hyphen)
- `exportName` - JavaScript export name

### Types vs Variations

Types are mutually exclusive behaviors (pick one), while variations are stackable visual modifications (combine many).

```html
<!-- Types: Can only be primary OR secondary -->
<ui-button primary>Save</ui-button>
<ui-button secondary>Cancel</ui-button>

<!-- Variations: Can combine multiple -->
<ui-button large fluid red>Delete Account</ui-button>
```

## Component Definition

### Content

Define slots and content areas

```json
"content": [
  {
    "name": "Icon",
    "attribute": "icon",
    "slot": "icon",
    "description": "include an icon",
    "exampleCode": "<ui-button icon=\"save\">Save</ui-button>"
  }
]
```

Content supports both attribute and slot syntax.

### Types

Define mutually exclusive behaviors

```json
"types": [
  {
    "name": "Emphasis",
    "attribute": "emphasis",
    "description": "be emphasized in a layout",
    "options": [
      {
        "name": "Primary",
        "value": "primary",
        "description": "be emphasized as the first action"
      },
      {
        "name": "Secondary",
        "value": "secondary",
        "description": "be emphasized as a secondary option"
      }
    ]
  }
]
```

### States

Define runtime state changes

```json
"states": [
  {
    "name": "Hover",
    "attribute": "hover",
    "description": "be hovered"
  },
  {
    "name": "Disabled",
    "attribute": "disabled",
    "description": "have interactions disabled",
    "options": [
      {
        "name": "Disabled",
        "value": "disabled",
        "description": "disable interactions"
      },
      {
        "name": "Clickable Disabled",
        "value": "clickable-disabled",
        "description": "allow interactions but appear disabled"
      }
    ]
  }
]
```

### Variations

Define stackable visual modifications

```json
"variations": [
  {
    "name": "Size",
    "attribute": "size",
    "description": "vary in size",
    "options": [
      {"name": "Small", "value": "small", "description": "appear small"},
      {"name": "Large", "value": "large", "description": "appear larger than normal"}
    ]
  },
  {
    "name": "Fluid",
    "attribute": "fluid",
    "description": "take the width of its container"
  }
]
```

## Configuration

### Settings

Define configuration properties

```json
"settings": [
  {
    "name": "Href",
    "type": "string",
    "attribute": "href",
    "description": "link to a webpage"
  },
  {
    "name": "Debounced",
    "type": "boolean",
    "attribute": "debounced",
    "defaultValue": false,
    "description": "debounce input value changes"
  }
]
```

### Events

Define custom events

```json
"events": [
  {
    "eventName": "change",
    "description": "occurs after the value changes",
    "arguments": [
      {
        "name": "value",
        "description": "the updated value"
      }
    ]
  }
]
```

### Plural Components

Support component collections

```json
{
  "supportsPlural": true,
  "pluralName": "Buttons",
  "pluralTagName": "ui-buttons",
  "pluralExportName": "UIButtons",
  "pluralDescription": "Buttons can exist together as a group",

  "pluralSharedVariations": ["size", "color", "floated"],

  "pluralOnlyVariations": [
    {
      "name": "Equal Width",
      "attribute": "equal-width",
      "description": "have the same width for each button"
    }
  ]
}
```

> [!info]
> Only share obvious visual variations (size, color). Not behavioral types (submit, reset).

## Writing Guidelines

### Description Format

Use imperative mood without the component name

```json
// Good
"description": "be emphasized"
"description": "appear small"
"description": "have interactions disabled"

// Bad
"description": "The button can be emphasized"
"description": "Makes the button appear small"
"description": "Button with disabled interactions"
```

### Usage Levels

Indicate feature commonality (1-5)

```json
{
  "name": "Size",
  "usageLevel": 1,  // Essential feature
  "description": "vary in size"
}

{
  "name": "Animated",
  "usageLevel": 3,  // Advanced feature
  "description": "animate to show hidden content"
}
```

1 = Essential, 2 = Common, 3 = Advanced, 4 = Specialized, 5 = Rare

### Example Configuration

Provide defaults for documentation

```json
"examples": {
  "defaultAttributes": {
    "icon": "check-circle"  // Icons always need a glyph
  },
  "defaultContent": "Click Me"
}
```

### Form Components

```json
"settings": [
  {"name": "Name", "type": "string", "attribute": "name"},
  {"name": "Value", "type": "string", "attribute": "value"},
  {"name": "Required", "type": "boolean", "attribute": "required", "defaultValue": false}
],
"events": [
  {"eventName": "change", "arguments": [{"name": "value"}]}
]
```

## Quick Reference

| Section | Purpose | Mutually Exclusive |
|---------|---------|-------------------|
| `types` | Core behaviors | Yes |
| `variations` | Visual modifications | No |
| `states` | Runtime changes | No |
| `settings` | Configuration | No |
| `content` | Slots/attributes | No |
| `events` | Custom events | No |
