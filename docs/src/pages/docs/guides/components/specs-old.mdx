Component specs are JavaScript modules that define a component's API. Specs enable automatic attribute mapping, support for three HTML dialects, and machine-readable documentation. All primitives in `@semantic-ui/core` use specs.

## What Specs Enable

Without a spec, components only support verbose attributes:

```javascript
// Without spec - manual attribute handling
defineComponent({
  tagName: 'ui-button',
  defaultSettings: {
    primary: false,
    size: 'medium',
  },
  // Only works: <ui-button primary="true">
});
```

With a spec, all three dialects work automatically:

```javascript
// With spec - automatic attribute mapping
import componentSpec from './specs/button.component.js';

defineComponent({
  tagName: 'ui-button',
  componentSpec,
  template,
  css,
  // All work:
  // <ui-button primary>            (standard)
  // <ui-button primary="true">     (verbose)
  // <ui-button class="ui primary"> (classic)
});
```

> [!warning]
> Specs are required to support all three dialects. Without a spec, only verbose syntax works.

## How Specs Work

A spec defines what becomes available as attributes. Here's a simple example:

```javascript
// alert.spec.js
export default {
  name: 'Alert',
  tagName: 'ui-alert',

  variations: [
    {
      name: 'Color',
      attribute: 'color',
      options: [
        { name: 'Red', value: 'red' },
        { name: 'Blue', value: 'blue' },
      ],
    },
    {
      name: 'Dismissible',
      attribute: 'dismissible',
    },
  ],
};
```

This spec makes these attributes available:

```html
<!-- Color variation with options -->
<ui-alert red>Error occurred</ui-alert>
<ui-alert blue>Info message</ui-alert>

<!-- Dismissible variation (boolean) -->
<ui-alert dismissible>You can close me</ui-alert>

<!-- Combine variations -->
<ui-alert red dismissible>Dismissible error</ui-alert>
```

All three dialects work automatically:

```html
<!-- Standard -->
<ui-alert red dismissible>Message</ui-alert>

<!-- Verbose -->
<ui-alert color="red" dismissible="true">Message</ui-alert>

<!-- Classic -->
<ui-alert class="ui red dismissible">Message</ui-alert>
```

## Spec Format

Specs are authored as JavaScript modules in `.spec.js` files.

### Simple Spec (No Imports)

Most specs are just plain objects with template literals:

```javascript
// divider.spec.js
export default {
  uiType: 'element',
  name: 'Divider',
  description: 'A divider visually segments content into groups',
  tagName: 'ui-divider',
  exportName: 'UIDivider',

  content: [
    {
      name: 'Text',
      attribute: 'text',
      description: 'include centered text',
      usageLevel: 1,
      exampleCode: `<ui-divider text="Or"></ui-divider>`,
    },
  ],

  types: [],
  states: [],
  variations: [],
  settings: [],
  events: [],
};
```

### Using Shared Constants

Import common variations to avoid repetition:

```javascript
// label.spec.js
import { SIZE_VARIATION } from '@semantic-ui/specs';

export default {
  name: 'Label',
  tagName: 'ui-label',
  exportName: 'UILabel',

  variations: [
    {
      name: 'Badge',
      attribute: 'badge',
      description: 'be used as a badge',
      usageLevel: 2,
    },
    SIZE_VARIATION,  // Includes all 8 size options
  ],
};
```

### Using Helpers

For complex specs, use helpers to reduce boilerplate:

```javascript
// button.spec.js
import {
  COLOR_OPTIONS,
  getStates,
  getVariations,
} from '@semantic-ui/specs';

export default {
  name: 'Button',
  tagName: 'ui-button',

  // Generate multiple states at once
  states: getStates(['hover', 'active', 'disabled', 'loading']),

  variations: [
    // Spread multiple variations
    ...getVariations(['floated', 'fluid', 'compact', 'size']),

    // Use shared options
    {
      name: 'Colored',
      attribute: 'color',
      description: 'be colored',
      options: COLOR_OPTIONS,  // All 13 colors
    },
  ],
};
```

### Template Literals

Use template literals for clean HTML examples:

```javascript
// Single example
exampleCode: `<ui-button icon="pause">Pause</ui-button>`

// Multiline
exampleCode: `
  <ui-button primary>Confirm</ui-button>
  <ui-button>Cancel</ui-button>
`

// Multiple examples (array)
exampleCode: [
  `<ui-button>
    <img src="/images/avatar.jpg" />
    Add User
  </ui-button>`,
  `<ui-button>
    <ui-image src="/images/avatar.jpg"></ui-image>
    Add User
  </ui-button>`,
]
```

> [!info]
> Specs must be pure data (JSON-serializable). The build validates this.

## Build Process

The build system generates files from `.spec.js` sources:

```
button.spec.js (source - you author)
    ↓
button.spec.json (snapshot for tooling)
button.component.js (runtime spec)
buttons.component.js (plural, if supported)
```

Your components import the generated `.component.js` file:

```javascript
import componentSpec from './specs/button.component.js';

export const UIButton = defineComponent({
  tagName: 'ui-button',
  componentSpec,  // Generated from button.spec.js
  template,
  css,
});
```

> [!info]
> Never edit generated files. Always edit the `.spec.js` source.

## Required Fields

Every spec needs these properties:

```javascript
{
  uiType: 'element',           // Always "element" for components
  name: 'Button',              // Display name
  description: 'A button...',  // What it does
  tagName: 'ui-button',        // HTML tag (needs hyphen)
  exportName: 'UIButton',      // JavaScript export name
}
```

## Types vs Variations

Types are mutually exclusive. Variations stack.

```html
<!-- Types: pick one -->
<ui-button primary>Save</ui-button>
<ui-button secondary>Cancel</ui-button>

<!-- Variations: combine many -->
<ui-button large fluid red>Delete</ui-button>
```

## Content

Define slots and content areas:

```javascript
content: [
  {
    name: 'Icon',
    attribute: 'icon',
    slot: 'icon',
    description: 'include an icon',
    exampleCode: `<ui-button icon="save">Save</ui-button>`,
  },
],
```

## Types

Define mutually exclusive behaviors:

```javascript
types: [
  {
    name: 'Emphasis',
    attribute: 'emphasis',
    description: 'be emphasized in a layout',
    options: [
      {
        name: 'Primary',
        value: 'primary',
        description: 'be emphasized as the first action',
      },
      {
        name: 'Secondary',
        value: 'secondary',
        description: 'be emphasized as a secondary option',
      },
    ],
  },
],
```

## States

Define runtime state changes:

```javascript
states: [
  {
    name: 'Disabled',
    attribute: 'disabled',
    description: 'have interactions disabled',
  },
],
```

## Variations

Define stackable visual modifications:

```javascript
variations: [
  {
    name: 'Size',
    attribute: 'size',
    description: 'vary in size',
    options: [
      { name: 'Small', value: 'small', description: 'appear small' },
      { name: 'Large', value: 'large', description: 'appear large' },
    ],
  },
  {
    name: 'Fluid',
    attribute: 'fluid',
    description: 'take the width of its container',
  },
],
```

## Settings

Define configuration properties:

```javascript
settings: [
  {
    name: 'Href',
    type: 'string',
    attribute: 'href',
    description: 'link to a webpage',
  },
  {
    name: 'Debounced',
    type: 'boolean',
    attribute: 'debounced',
    defaultValue: false,
    description: 'debounce input value changes',
  },
],
```

## Events

Define custom events:

```javascript
events: [
  {
    eventName: 'change',
    description: 'occurs after the value changes',
    arguments: [
      {
        name: 'value',
        description: 'the updated value',
      },
    ],
  },
],
```

## Plural Support

Define collection components:

```javascript
{
  supportsPlural: true,
  pluralName: 'Buttons',
  pluralTagName: 'ui-buttons',
  pluralExportName: 'UIButtons',
  pluralDescription: 'Buttons can exist together as a group',

  // Which variations the plural shares
  pluralSharedVariations: ['size', 'color', 'floated'],

  // Variations only for plural
  pluralOnlyVariations: [
    {
      name: 'Equal Width',
      attribute: 'equal-width',
      description: 'have the same width for each button',
    },
  ],
}
```

## Shared Terms

The `@semantic-ui/specs` package provides reusable constants and helpers.

### Complete Variations

Ready-to-use variations with all options defined:

```javascript
import {
  SIZE_VARIATION,        // 8 sizes: mini → massive
  COLORED_VARIATION,     // 13 colors
  FLOATED_VARIATION,     // left, right
  ATTACHED_VARIATION,    // top, bottom, left, right, both
  COMPACT_VARIATION,     // compact, very compact
  PADDED_VARIATION,      // padded, very padded
  CIRCULAR_VARIATION,    // boolean
  FLUID_VARIATION,       // boolean
} from '@semantic-ui/specs';

export default {
  variations: [
    SIZE_VARIATION,      // Just drop it in
    COLORED_VARIATION,
  ],
};
```

### Options Arrays

Pre-defined option arrays for custom variations:

```javascript
import {
  SIZE_OPTIONS,          // 8 size options
  COLOR_OPTIONS,         // 13 color options
  FLOATED_OPTIONS,       // left, right
  ATTACHED_OPTIONS,      // 5 position options
  COMPACT_OPTIONS,       // 2 levels
  PADDED_OPTIONS,        // 2 levels
  HORIZONTAL_ALIGNED_OPTIONS,  // left, center, right
  VERTICAL_ALIGNED_OPTIONS,    // top, middle, bottom
  EMPHASIS_OPTIONS,      // primary, secondary, tertiary
} from '@semantic-ui/specs';

export default {
  variations: [
    {
      name: 'Colored',
      attribute: 'color',
      options: COLOR_OPTIONS,  // All colors pre-defined
    },
  ],
};
```

### State Constants

Common states:

```javascript
import {
  HOVER_STATE,
  FOCUS_STATE,
  ACTIVE_STATE,
  LOADING_STATE,
  PRESSED_STATE,
  DISABLED_STATE,  // Has options: disabled, clickable-disabled
} from '@semantic-ui/specs';

export default {
  states: [
    HOVER_STATE,
    ACTIVE_STATE,
    DISABLED_STATE,
  ],
};
```

### Helper Functions

**`getStates(names)`** - Get multiple states at once:

```javascript
states: getStates(['hover', 'focus', 'active', 'disabled', 'loading'])
```

**`getVariations(names)`** - Get multiple variations at once:

```javascript
variations: [
  ...getVariations(['size', 'fluid', 'compact', 'floated']),
  // Add custom variations
]
```

**`modifyVariation(variation, overrides)`** - Customize a variation:

```javascript
import { ATTACHED_VARIATION, modifyVariation } from '@semantic-ui/specs';

variations: [
  modifyVariation(ATTACHED_VARIATION, {
    usageLevel: 3,  // Change from default
  }),
]
```

**`addOptionExamples(options, examples)`** - Add example code to options:

```javascript
import { ATTACHED_OPTIONS, addOptionExamples } from '@semantic-ui/specs';

options: addOptionExamples(ATTACHED_OPTIONS, {
  'top-attached': `<ui-button top-attached>Action</ui-button>`,
  'bottom-attached': `<ui-button bottom-attached>Action</ui-button>`,
})
```

## Writing Style

### Descriptions

Use imperative mood without the component name:

```javascript
// Good
description: 'be emphasized'
description: 'appear small'
description: 'have interactions disabled'

// Bad
description: 'The button can be emphasized'
description: 'Makes the button appear small'
```

### Usage Levels

Indicate feature commonality (1-5):

```javascript
{
  name: 'Size',
  usageLevel: 1,  // Essential
  description: 'vary in size',
}

{
  name: 'Animated',
  usageLevel: 3,  // Advanced
  description: 'animate to show hidden content',
}
```

Scale: 1 = Essential, 2 = Common, 3 = Advanced, 4 = Specialized, 5 = Rare

## Quick Reference

| Section | Purpose | Mutually Exclusive |
|---------|---------|-------------------|
| `types` | Behaviors | Yes |
| `variations` | Visual mods | No |
| `states` | Runtime changes | No |
| `settings` | Configuration | No |
| `content` | Slots | No |
| `events` | Custom events | No |

## When to Use Specs

**Use specs when:**
- You need all three HTML dialects
- Building a design system
- Want AI assistants to understand your components
- Creating plural components with shared variations

**Skip specs when:**
- Building one-off internal components
- Prototyping with rapidly evolving APIs
- Simple components where overhead isn't justified
