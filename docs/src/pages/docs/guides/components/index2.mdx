## The Web Component Problem

[Web Components](https://developer.mozilla.org/en-US/docs/Web/API/Web_components) are the right foundation for UI development—they're native to the browser, work across frameworks, and don't require compilation. **But** vanilla Web Components force developers into painful trade-offs: verbose boilerplate for basic state management, awkward Shadow DOM querying, manual dependency tracking, and imperative patterns that feel dated compared to modern frameworks.

This creates an uncomfortable choice: adopt a framework and accept its lock-in, build complexity, and interoperability costs—or use the standard and lose the developer experience that makes UI work productive.

Semantic UI resolves this tension. It provides the authoring experience developers expect—[reactive state](/docs/guides/reactivity), [declarative templates](/docs/guides/templates), [scoped styling](/docs/guides/components/styling)—while producing standard Web Components that work everywhere, **without a compilation step**.

> **Getting Started:** The [interactive tutorial](/learn/selection) offers a hands-on introduction before diving into these technical guides.

### What This Solves

| Vanilla Web Component Pain | Semantic UI Solution |
|----------------------------|----------------------|
| Manual DOM updates when state changes | [Signals-based reactivity](/docs/guides/reactivity) with automatic dependency tracking |
| String concatenation or imperative rendering | [AST-based templates](/docs/guides/templates) with expressions, loops, and conditionals |
| `querySelector` breaks across Shadow DOM | [Query library](/docs/guides/query) designed for [Shadow DOM traversal](/docs/guides/query/shadow-dom) |
| Verbose `addEventListener` boilerplate | [Declarative event binding](/docs/guides/components/events) with delegation support |
| No standard approach to keyboard handling | [Declarative key bindings](/docs/guides/components/keys) with sequences and combinations |
| CSS leaks or overly specific selectors | [Scoped styling](/docs/guides/components/styling) via Shadow DOM with CSS variable theming |

### Framework Compatibility

Components work natively in <a href="https://react.dev/" target="_blank" rel="noopener noreferrer">React</a>, <a href="https://vuejs.org/" target="_blank" rel="noopener noreferrer">Vue</a>, <a href="https://angular.io/" target="_blank" rel="noopener noreferrer">Angular</a>, or any framework that supports custom elements—because they *are* custom elements. No wrappers, no adapters, no framework-specific builds.

Components defined with [`defineComponent`](/docs/guides/components/create) can register a `tagName` for direct HTML use, or export without one for use as [subtemplates](/docs/guides/templates/subtemplates) within other components.

## Defining Components

[`defineComponent`](/docs/guides/components/create) registers a standard custom element. All framework features—templating, state, events, styling—are configured in a single definition object:

```javascript
defineComponent({
  tagName: 'my-component',
  template: '...',
  css: '...',
  defaultState: { ... },
  settings: { ... },
  createComponent: () => ({ ... }),
  onCreated: () => { ... },
  onRendered: () => { ... },
  onDestroyed: () => { ... },
});
```

## Templating Without String Manipulation

Vanilla Web Components typically require string concatenation or verbose `document.createElement` calls to render dynamic content. The [templating system](/docs/guides/templates) replaces this with declarative syntax—[expressions](/docs/guides/templates/expressions), [conditionals](/docs/guides/templates/conditionals), [loops](/docs/guides/templates/loops), [slots](/docs/guides/templates/slots)—that compiles to an AST for efficient updates.

```sui
{#each user in users}
  <div class="user">
    {#if user}
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    {else}
      <p>No info provided.</p>
    {/if}
  </div>
{/each}
```

## Styling That Actually Scopes

Global CSS in component-based applications leads to specificity wars, naming conventions (BEM, CSS Modules), or build-time extraction. Shadow DOM provides true encapsulation, but working with it requires understanding CSS variable inheritance and `:host` selectors. The [styling system](/docs/guides/components/styling) handles this integration:

```css
:host {
  --counter-padding: var(--padding);
  --counter-value-color: var(--primary-text-color);
}
.counter {
  padding: var(--counter-padding);

  .value {
    color: var(--counter-color);
  }
}
```

## Events Without Boilerplate

The standard `addEventListener` / `removeEventListener` pattern requires manual cleanup, doesn't support delegation naturally, and scatters event logic across lifecycle methods. [Declarative events](/docs/guides/components/events) bind handlers to selectors, support delegation, and clean up automatically:

```javascript
const events = {
  'click .increment': ({ self }) => self.increment(),
  'click .decrement': ({ self }) => self.decrement(),
};
```

Listen to [events from other components](/docs/guides/components/events#custom-event-data):
```javascript
const events = {
  'increment ui-counter, decrement ui-counter': ({ self }) => self.logValue(),
};
```

Bind [global events](/docs/guides/components/events#global-events) tied to component lifecycle:
```javascript
const events = {
  'global hashchange window': ({ self }) => self.updateSomething(),
};
```

Dispatch custom events for parent components to consume:
```javascript
const createComponent = ({state, dispatchEvent}) => ({
  increment(amount) {
    state.counter.increment(amount);
    dispatchEvent('increment', { counter: state.counter.value, amount });
  },
});
```

## Keyboard Handling That Scales

Implementing keyboard shortcuts typically means parsing `event.key`, tracking modifier state, and managing focus. [Declarative key bindings](/docs/guides/components/keys) handle combinations and sequences with automatic scope management:

```javascript
const keys = {
  'up': ({ self }) => self.decrement(),
  'down': ({ self }) => self.increment(),
  'shift + up': ({ self }) => self.decrement(10),
  'shift + down': ({ self }) => self.increment(10),
};
```
