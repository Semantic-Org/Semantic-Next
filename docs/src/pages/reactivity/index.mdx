## Understanding Reactivity

Reactivity is the mechanism by which changes in data automatically propagate to update dependent code or UI elements. Semantic UI implements reactivity using **Signals**.

### Signals

[Signals](/reactivity/variables) are reactive primitives that hold a value and track dependencies. When a signal's value changes, it notifies any dependent computations ([Reactions](#reactions)) that they need to re-run.

Signals track dependencies automatically when their value is accessed (e.g., via `.value` or `.get()`) within a reactive context. Learn more about [Signal dependencies](/api/reactivity/dependency).

### Reactions

A [Reaction](/api/reactivity/reaction) is a function designed to re-run automatically whenever any signal it depends on changes. Accessing a signal's value inside a reaction creates this dependency.


> **Naming Conventions** Signals implementations vary in their naming conventions a reactive context is called ***watcher***  in the [signals proposal](https://github.com/tc39/proposal-signals), a **computation** in [Preact](https://preactjs.com/guide/v10/signals/) and `watch` in [Lit](https://lit.dev/docs/data/signals/).


## Usage


### Standalone Usage
The [`@semantic-ui/reactivity`](/api/reactivity) package can be used independently from the component framework. It exports core classes like [`Signal`](/api/reactivity/signal), [`Reaction`](/api/reactivity/reaction), and [`Dependency`](/api/reactivity/dependency).

```javascript
import { Signal, Reaction } from '@semantic-ui/reactivity';

const counter = new Signal(1);

Reaction.create(() => {
  console.log(counter.value);
  // outputs 1 2
});
counter.increment();
```

### Component Integration

When building [Semantic UI components](/components), the reactivity system is seamlessly integrated:

*   Reactive state is managed using [Signals](/components/state).
*   [Templates](/templates) automatically react to state changes.
*   [Lifecycle callbacks](/components/lifecycle#callback-arguments) provide access to reactivity primitives like `signal` (to create new signals) and `reaction` (to create reactive computations scoped to the component's lifecycle).

> Learn more about using reactivity within components in the dedicated [Component Reactivity](/components/reactivity) guide.


```javascript
const createComponent = ({ self, reaction, signal }) => ({
  value: signal(0),
  initialize() {
    // this will log whenever the value updates
    reaction(() => {
      console.log(self.value);
    });
  }
});
```

## Example

### Example: Birthday Calendar

This conceptual example illustrates how Signals and Reactions work:

Imagine tracking the current day using a `Signal`. A `Reaction` can then depend on this signal to automatically check for birthdays whenever the day changes.

```javascript
const today = new Signal( new Date() );

// each day when you wake up
const newDay() => {
  today.set(new Date());
}

const checkBirthdays = Reaction(() => {
  const today = today.get();
  each(friendsBirthdays, (birthday) => {
    if(today == birthday) {
      // wish them happy birthday
    }
    else {
      // no birthdays today
    }
  });
}
```
