## Using Query in Browser Environments

While Query is designed to integrate seamlessly with Semantic UI components, it's equally powerful as a standalone utility for DOM manipulation in any browser environment. This guide explains how to use Query independently in your web projects.

## Global Exports

The simplest way to use Query in a browser is to make the `$` and `$$` functions globally available using the `exportGlobals` function:

```javascript
import { exportGlobals } from '@semantic-ui/query';

// Make Query's functions available globally
exportGlobals();

// Now you can use $ and $$ directly
$('.button').on('click', () => console.log('Clicked!'));
$$('ui-component .content').text('Updated content');
```

This approach allows you to use Query's functions anywhere in your code, similar to how jQuery works when included in a page.

### Controlling What Gets Exported

You can customize which functions are exported to the global scope:

```javascript
import { exportGlobals } from '@semantic-ui/query';

// Only export $ (not $$ or Query)
exportGlobals({
  $: true,
  $$: false,
  Query: false
});
```

This flexibility helps avoid conflicts with other libraries while still leveraging Query's capabilities.

## Managing Library Conflicts

If you're working in an environment with multiple libraries that use the `$` symbol (like jQuery), Query provides ways to avoid conflicts.

### Restoring Global Variables

You can temporarily use Query and then restore the original global variables:

```javascript
import { exportGlobals, restoreGlobals } from '@semantic-ui/query';

// Save the original globals and use Query globally
exportGlobals();

// Do some work with Query
$('div').addClass('processed');

// When finished, restore the original globals
restoreGlobals();

// $ and $$ now refer back to their original values
```

### No-Conflict Mode

Similar to jQuery, Query provides a `noConflict` method to yield control of the global variables:

```javascript
import { exportGlobals } from '@semantic-ui/query';

// Export Query to global scope
exportGlobals();

// Store a reference and release the global variables
const $q = $.noConflict();

// Now use $q instead of $
$q('.content').addClass('active');
```

## Custom Aliases

For maximum flexibility, you can create your own alias for Query without touching the global scope:

```javascript
import { useAlias } from '@semantic-ui/query';

// Create a custom alias
const $q = useAlias();

// Use your custom alias
const $elements = $q('.element');
$elements.addClass('selected');
```

This approach is ideal for modern JavaScript applications where you want to avoid global variables altogether.

## CDN Integration

Query can be loaded directly from a CDN for quick prototyping or small projects:

```html
<script type="module">
  // Import from CDN
  import { $, $$ } from 'https://unpkg.com/@semantic-ui/query';
  
  // Use Query when the DOM is ready
  document.addEventListener('DOMContentLoaded', () => {
    $('.content').html('<p>Ready to go!</p>');
  });
</script>
```

## Integration Patterns

### Stand-alone Usage

Use Query as a lightweight jQuery alternative:

```javascript
import { $ } from '@semantic-ui/query';

// DOM ready equivalent
document.addEventListener('DOMContentLoaded', () => {
  // Traditional DOM manipulation
  $('.tabs')
    .on('click', '.tab', function() {
      // Handle tab clicks
      $(this)
        .addClass('active')
        .siblings()
        .removeClass('active');
    });
});
```

### Within Module Systems

Use Query inside a modern JavaScript module:

```javascript
// ui-manager.js
import { $, $$ } from '@semantic-ui/query';

export class UIManager {
  initialize() {
    this.setupEventHandlers();
    this.setupComponents();
  }
  
  setupEventHandlers() {
    $('.toggle-button').on('click', () => this.toggleContent());
  }
  
  setupComponents() {
    $$('ui-menu').settings({
      vertical: true,
      active: 0
    });
  }
  
  toggleContent() {
    $('.content-panel').toggleClass('visible');
  }
}
```

### With Web Components

Use Query to enhance your custom web components:

```javascript
import { $, $$ } from '@semantic-ui/query';

class ExpandablePanel extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
    this.shadowRoot.innerHTML = `
      <div class="panel">
        <header class="panel-header">
          <h3><slot name="title">Panel</slot></h3>
          <button class="expand-toggle">+</button>
        </header>
        <div class="panel-content">
          <slot></slot>
        </div>
      </div>
      <style>
        /* Styles here */
      </style>
    `;
    
    // Use $ with this.shadowRoot as the context
    $(this.shadowRoot)
      .find('.expand-toggle')
      .on('click', () => this.toggleExpand());
  }
  
  toggleExpand() {
    $(this.shadowRoot)
      .find('.panel')
      .toggleClass('expanded');
  }
}

customElements.define('expandable-panel', ExpandablePanel);
```

## Best Practices

1. **Import Only What You Need**
   
   For modern applications using bundlers like webpack or Rollup, import only the specific functions you need:
   
   ```javascript
   // Import only the $ function if you don't need $$
   import { $ } from '@semantic-ui/query';
   ```

2. **Avoid Global Pollution**
   
   For larger applications, avoid exporting to globals and instead use modules:
   
   ```javascript
   // Better for larger applications
   import { $ } from '@semantic-ui/query';
   
   function setupUI() {
     $('.content').addClass('ready');
   }
   ```

3. **Combine with Native APIs When Appropriate**
   
   Query works well alongside native DOM APIs:
   
   ```javascript
   // Use native methods when convenient
   const mainElement = document.getElementById('main');
   
   // Then enhance with Query
   $(mainElement)
     .find('.content')
     .addClass('visible');
   ```

4. **Use Performance Optimizations**
   
   Cache Query objects when reusing them:
   
   ```javascript
   // Cache for reuse
   const $sidebar = $('.sidebar');
   
   function expandSidebar() {
     $sidebar.addClass('expanded');
   }
   
   function collapseSidebar() {
     $sidebar.removeClass('expanded');
   }
   ```
